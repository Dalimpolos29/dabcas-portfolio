## The idea

A portfolio has two audiences with different needs. A hiring manager wants evidence, quickly. A
prospective client wants to know whether I can be trusted with their budget. The same site has to
serve both without feeling like it's hedging.

## How it's built

Next.js App Router with everything statically generated at build time. Case studies live as MDX
files under `content/projects/`, parsed with `gray-matter` and rendered through `next-mdx-remote`.
Adding a project means adding a file — there's no CMS to log into and no deploy step to remember.

The design system is a set of CSS custom properties consumed by Tailwind v4's `@theme` block.
Changing the accent colour is a one-line edit, and light/dark are the same tokens with different
values rather than two parallel sets of classes.

## Decisions worth explaining

**Files over a CMS.** A headless CMS adds an account, a network dependency and a free tier that
might disappear. Markdown in the repository is versioned, diffable, and works offline.

**One config file.** Name, role, availability, services, contact details and social links all live in
`src/lib/site.ts`. Nothing personal is hardcoded in a component, so the whole site can be re-pointed
at a different person or brand in one edit.

## Outcome

Fully static, no client-side data fetching, and a new case study takes about as long to publish as
it takes to write.
